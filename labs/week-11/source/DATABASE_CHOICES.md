## ข้อ 1 — ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB

โปรเจกต์นี้เลือก SQLite เพราะข้อมูลมีโครงสร้างชัดเจนและมีความสัมพันธ์ระหว่างตาราง — ตาราง `requests` อ้างอิงไปหาตาราง `users` ผ่าน `requester_id` ซึ่งเป็น foreign key แบบ relational ที่ SQLite จัดการได้ดีมาก

MongoDB เป็น NoSQL ที่เหมาะกับข้อมูลที่โครงสร้างยืดหยุ่นหรือไม่แน่นอน แต่ข้อมูลคำร้องของเรามีทุก field ชัดเจนตั้งแต่แรก ไม่จำเป็นต้องเก็บแบบ document ที่แต่ละชิ้นโครงสร้างต่างกัน นอกจากนี้ SQLite ไม่ต้องติดตั้ง server แยก ทำงานจากไฟล์เดียว เหมาะกับขนาดโปรเจกต์นี้

## ข้อ 2 — ถ้าเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง

ตลอดวิชานี้เปลี่ยนแหล่งข้อมูล 4 ครั้ง (JSON → in-memory → localStorage → SQLite) แต่ละครั้งแก้เฉพาะชั้น **service** ไฟล์เดียว controller และ route ไม่เปลี่ยนเลย ทำได้เพราะทุกแหล่งข้อมูลที่ใช้มาเป็นแบบ **sync** — ผลลัพธ์คืนค่าทันทีโดยไม่ต้องรอ

แต่ถ้าเปลี่ยนไป MongoDB จะกระทบ **2 ชั้น** คือทั้ง service และ controller เพราะ MongoDB driver เป็น async ทุก query ต้องใช้ `await` ก่อนได้ผลลัพธ์ ฟังก์ชันใน service จึงต้องเป็น `async function` และ controller ที่เรียก service ก็ต้องใส่ `await` ด้วย นี่คือความต่างที่ทำให้การเปลี่ยนครั้งนี้กระทบมากกว่าครั้งก่อน ๆ

## ข้อ 3 — async จำเป็นเมื่อไร ไม่จำเป็นเมื่อไร

`async/await` จำเป็นเมื่อต้องรอการทำงานที่ใช้เวลาและไม่รู้ว่าจะเสร็จเมื่อไร โดยเฉพาะเมื่อฐานข้อมูลอยู่บนเครื่องอื่น (network I/O) เช่น MongoDB Atlas หรือ Turso ที่ต้องส่ง request ผ่านอินเทอร์เน็ตและรอ response กลับมา ถ้าไม่ใช้ async Node.js จะบล็อกรอและไม่รับ request อื่นในระหว่างนั้น

ไม่จำเป็นเมื่อการทำงานเสร็จทันทีแบบ synchronous เช่น SQLite ที่ใช้ `node:sqlite` — ฐานข้อมูลอยู่บนดิสก์เครื่องเดียวกัน OS อ่านได้เร็วมาก ผลลัพธ์คืนทันที ไม่มีการรอผ่านเครือข่าย จึงใช้ sync ได้โดยไม่มีปัญหา
